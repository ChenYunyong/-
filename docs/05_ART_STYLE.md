# 05 — 美术风格规范（ART STYLE）

> 状态：`FROZEN-DRAFT`（待用户批准）｜版本 v0.1.0｜维护者 DSH（执行 Codex Visual Reviewer）
> 本文件定义「什么是对的像素风」，是美术审查的判定依据。

## 1. 风格定位

**日式 Q 版精致像素风**（Japanese chibi refined pixel art）。

### 1.1 关键词白名单（必须命中）

```
日式 · Q版 · 像素 · 幻想 · 浮空岛 · 工坊 · 机械 · 蓝图 · 温暖 · 清爽 · 精致 · 可爱
```

### 1.2 关键词黑名单（出现即打回）

```
写实 · 厚重欧美奇幻 · 暗黑 · 赛博朋克 · 高噪声机械 · 军事写实 · 广告式大场景堆料
```

## 2. 参考图的真实性质（2026-10-03 实测，必须先读）

| 项 | 实测值 |
|---|---|
| 分辨率 | 1672 × 941（三张一致，16:9） |
| 色彩模式 | RGB，8-bit，无 alpha |
| 唯一颜色数 | A: 96,201 · B: 86,165 · C: 104,769 |

**结论：三张参考图是「像素风格化的高分辨率插画」，不是真正的像素画。**

这决定了整条美术工作方式：

1. ❌ **不得**把参考图缩放后直接当游戏素材。86k~105k 色降到 320×180 只会得到糊成一团的结果，且会连带引入渐变与柔边。
2. ✅ 参考图的作用是**构图、配色、氛围、信息密度**的依据。正式素材必须按 320×180 网格**手工重绘**。
3. ✅ 颜色必须从参考图**取色后重新设计**为 ≤12 色的受限调色板（取色结果见 `04_COLOR_SYSTEM.md` §2）。
4. ❌ 不得以「参考图就是这样」为由引入渐变、抗锯齿、柔和阴影、模糊辉光 —— 那些是插画特征，不是像素规范。
5. ⚠ 参考图的蓝是**粉彩天空蓝**（`#77B7F7`~`#D7E7F7`），棕是**低饱和偏红**（`#372727`~`#573737`）。画素材时以此为准，不要凭印象调色。

## 2.1 像素网格纪律（最容易被破坏的一条）

| 项 | 规定 |
|---|---|
| 基准分辨率 | **320 × 180** 逻辑像素（16:9），整数倍放大到目标窗口 |
| 放大方式 | **Nearest / 整数倍**，禁止任何插值缩放 |
| 角色/敌人尺寸 | 站立角色 32×32 或 48×48；敌人 24×24 ~ 64×64；CORE 64×64 |
| 图标尺寸 | 16×16 / 24×24 / 32×32 三档，禁止随意尺寸 |
| 禁止 | 半像素、非整数位移、旋转后不做像素对齐、混用两种像素密度 |

- 所有素材必须**逐像素对齐网格**，不得出现模糊边缘。
- 双端缩放：手机端使用整数倍缩放 + letterbox，禁止拉伸。

## 3. 描边与明暗

- 角色/敌人：**1px 深色描边**（`NAVY_900` 或更深的固有色，禁止纯黑描边）。
- 光源方向统一为**左上**。
- 每个对象最多 **3 级明度**（暗 / 中 / 亮），Q 版不允许堆 5 级渐变。
- 禁用抖动（dithering）作为主要过渡手段；仅允许在极少数大面积渐变背景中少量使用。

## 4. 颜色数量

- **单个交互对象**（角色、敌人、节点、武器、图标、单个特效）调色板 **≤ 12 色**（含描边与透明）。
- **背景 / 大场景允许使用分区调色板**（不同区域各自 ≤12 色），但**不得**因此让整个画面变成无节制的渐变堆叠。
  这条用于消除「整屏只能 12 色」的误读（Codex 审查提出）。
- 全部颜色必须映射到 `04_COLOR_SYSTEM.md` 的 Token。
- 禁止在素材里引入未登记的近似色。

## 5. 分类规格

### 5.1 UI
- 面板：像素角（不做圆角抗锯齿），统一 1px 描边 + 1px 内高光。
- 按钮：5 态（Normal / Hover / Pressed / Disabled / Selected），见 `06_UI_UX_STANDARD.md`。
- 蓝图连线：2px 宽，激活态带轻微流光（FX 层，不影响逻辑）。

### 5.2 Icon
- 24×24 基准，轮廓优先，缩到 16×16 仍可辨识。
- 必须与节点/武器/敌人的实际功能语义一致，禁止「好看但看不出用途」的图标。

### 5.3 Character（工坊少女、猫咪）
- Q 版比例：头身比约 **1:2 ~ 1:3**。
- 表情靠眼睛与简单口型，禁止写实五官。
- 站立动画 ≥ 2 帧（呼吸），移动 ≥ 4 帧。

### 5.4 Enemy
- 必须一眼能读出「威胁等级」与「接近方式」。
- 禁止写实怪物、血腥、露骨恐怖元素。

### 5.5 Node（蓝图节点卡）
- 必须一眼区分 `CORE` / `FUNCTION` / `WEAPON` 三类。
- 接口（Port）位置与数量必须在美术上清晰可数。

### 5.6 Weapon
- 机械结构必须**可读**：看得出能量从哪进、从哪出。
- 禁止高噪声（一堆无意义小零件）——黑名单明确禁止。

### 5.7 FX
- 伤害/爆炸/过热必须克制：单次特效 ≤ 0.4s，禁止全屏闪白。
- 特效不得遮挡关键信息（HP、Heat、连接线）。
- 必须考虑光敏安全：禁止高频闪烁（≥3Hz 的全屏闪烁）。

### 5.8 Background
- 浮空岛 / 工坊内景，低对比度、低细节，作为背景不得抢前景。
- 参考图的构图与氛围为准，不得自行加戏。

### 5.9 Sprite Sheet
- 统一排列规则、统一边距、统一命名（见 `07_ASSET_PIPELINE.md` §3）。
- 必须提供 `.png` + 可选 `.json` 帧数据；帧数据必须能被 Godot `AnimatedSprite2D` 或 `SpriteFrames` 直接使用。

## 6. 三张参考图的地位

| 参考 | 对应状态 | 作用 |
|---|---|---|
| Reference A | `MAIN_MENU` | 开始界面 UI 与美术方向 |
| Reference B | `PREPARATION` | 蓝图 / 战前整备 UI 与美术方向 |
| Reference C | `COMBAT` | 自动战斗画面 UI 与美术方向 |

它们是**游戏 UI 与美术设计参考**：

- ✅ 是：布局依据、颜色依据、氛围依据、密度依据。
- ❌ 不是：宣传图、广告 Key Art。
- ❌ 不得为了「视觉冲击」随意塞满装饰、粒子、面板和文字。

**克制度是本项目的审美核心**：宁可少，不可乱。
