## 0. v0.1.1 修订说明

v0.1.0 的颜色是按用户文字描述（深海军蓝 / 天空蓝 / 黄铜金 / 工坊棕 / 战斗红 / 热橙）**推测**的。
2026-10-03 拿到三张参考图（A 开始界面 / B 蓝图整备 / C 自动战斗）后，DSH 对原图做了**逐像素取色实测**，据此重写本表。

- 蓝色组与棕色组 **改动较大**（v0.1.0 过于饱和 / 过于橙，与参考图不符）。
- 红色组与橙色组 **保持不变** —— 参考图中没有可测量的基准，理由见 §3.6。
- 所有标 `实测` 的色值来自参考图；标 `推导` 的色值是为补齐层级而由实测值外推的。

## 1. 第一原则

正式项目**禁止**到处随手写 `Color("#xxxxxx")`。所有颜色必须来自统一 Palette，并按语义命名引用。

```gdscript
# 正确
var panel_bg: Color = Palette.get_color(Palette.Key.NAVY_800)

# 禁止
var panel_bg := Color("#172747")
```

### 2.2 三条关键发现

1. **蓝色远比 v0.1.0 猜测的浅**。参考图的蓝是 `#77B7F7 → #D7E7F7` 的**粉彩天空蓝**，不是 v0.1.0 里那种饱和电光蓝（`#3E8BFF`）。v0.1.0 的 `BLUE_500/400/300/100` 在参考图中**根本不存在**，已删除。
2. **棕色是低饱和偏红，不是橙**。实测为 `#372727 / #472727 / #573737`（R > G ≈ B），v0.1.0 的 `#6B4A2F` 偏橙，已修正。
3. **白色用量很大**（A 中 `#F7F7F7` 占 1.87%）。v0.1.0 写的「像素风中少用纯白」不成立，已解除该限制。

## 3.10 特效（FX）三层结构规则（v0.1.3 新增）

Codex 目视 Reference C 的结论：战斗中的**子弹、电锚、激光不是单色粉彩蓝**，而是三层结构。
仅用 `BLUE_500 #77B7F7` 画弹体，在天空蓝背景上会丢失可读性。

**强制三层**（缺一层即打回）：

| 层 | 用色 | 作用 |
|---|---|---|
| 芯 | `BLUE_050 #E7EFF7` 或 `WHITE #F7F7F7` | 最亮的能量核心 |
| 体 | `BLUE_FX_600 #3EA6FF`（亮边）/ `BLUE_500` | 能量主体 |
| 描边 | `NAVY_900 #0F1B33` 1px | 与任何背景分离 |

- `BLUE_FX_600` **仅限 FX**：弹体、电击、激光、能量边。**禁止**用于 UI、文字、按钮、图标。
- 爆炸 / 过热用同样的三层法：`ORANGE_300` 芯 → `ORANGE_500` 体 → `NAVY_900` 描边。
- 该规则同时满足 `05_ART_STYLE.md` §5.7「特效不得遮挡关键信息」与「禁止高频闪烁」。

## 4. 色彩硬规则

1. 正式颜色**必须**在本文件中登记（Token + Hex + 用途 + 来源 + 可用域）。
2. 每个颜色必须有**语义名**，禁止 `color_1`、`blue2` 之类。
3. 必须标明是否可用于 `UI` / `Char` / `FX`。
4. **同一用途不得出现近似色**。同色组**允许** 3–6 档明度阶梯（`NAVY_*` / `BLUE_*` / `BROWN_*` 本身就是阶梯），**但每一档必须有明确且不重叠的用途**；两个 Token 的用途若可以互换，就说明多了一个。
   - v0.1.1 曾写「同一色相 10° 内不得出现两个 Token」，该条**无法执行且与本表自相矛盾**（阶梯本身就是同色相），已于 v0.1.2 废止。
   - 实测中出现的连续梯度（如 `#97C7F7 / #A7D7F7 / #B7D7F7`）是**参考图的插画渐变特征**，不是要求逐级建模 —— 只登记上表 5 级即可。
5. **禁止两个 Token 使用完全相同或肉眼难分的 Hex**。v0.1.1 中 `WARM_500` 与 `BROWN_200` 都是 `#977777`（同源于实测桶 `#907070`），属同一个颜色的两个名字，已于 v0.1.2 合并为单一 Token。
6. 新增颜色流程：提出 → DSH 检查（是否真的必要 / 能否复用现有 Token）→ 记入 `12_CHANGELOG.md`。
7. 涉及整体视觉改变的，必须再交**用户确认**（GATE 3）。
8. `assets/palette.tres` 的 Token 名必须与本文表格**逐字一致**。
9. 任何任务中出现裸 `Color("#...")` 一律打回，除非是 `palette.gd` 内的定义处。
10. 标 `UNVERIFIED-AGAINST-REFS` 的颜色在使用前必须先经用户确认。

## 5. 文字对比度要求

- 正文文字与背景对比度 **≥ 4.5:1**（WCAG AA）；大号标题与**图形** **≥ 3:1**。
- 红/橙不得作为**唯一**状态区分手段（色盲），必须同时有图标或形状差异。

### 5.2 由本表得出的两条规则

1. **`BLUE_500` 不作小号正文** —— 但理由**不是**对比度不足（实测 6.98:1，达标）。
   v0.1.1 写的「亮度接近度不足」是**错误的**（Codex 审查发现，已复算确认）。
   真正的理由是：`BLUE_500` 是**能量/激活的语义色**，用作正文会抢焦点并稀释「激活」的含义。
2. **`GREY_500` 只允许出现在 `NAVY_800`（4.80:1）上，不得出现在 `NAVY_700`（3.84:1）上**。
   这条直接决定了 `06_UI_UX_STANDARD.md` 里 Disabled 按钮的底色。

## 6. `assets/palette.tres` 规范（Stage 1 实现）

Stage 0 仅冻结 schema，**不创建可能损坏的资源文件**。

Stage 1 由 Claude Lead Developer 实现（任务 S1-03）：

```
scripts/data/palette.gd      # class_name Palette extends Resource
    - enum Key { ... 与 §3 表格逐字一致 ... }
    - @export var colors: Dictionary
    - static func get_color(key: Key) -> Color

assets/palette.tres          # 唯一的颜色事实来源
```

强制要求：

- 所有色值只在 `palette.tres` 中出现一次。
- `Palette.get_color()` 是取色唯一入口。
- Editor 中修改 `palette.tres` 后，全项目表现必须同步变化。
- 禁止在 `.tscn` 中直接写十六进制颜色（Theme 必须引用 Palette）。

## 7. 主题（Theme）规则

- 全局 `Theme` 资源引用 Palette Token，不在控件上零散覆盖颜色。
- 允许的局部覆盖场景：HP 条变色、Heat 条变色、禁用态 —— 且必须用 Token。
- 禁止为「好看」临时调一个色再忘记登记。
