# 09 — 测试规范（TEST STANDARD）

> 状态：`FROZEN-DRAFT`（待用户批准）｜版本 **v0.1.1**｜维护者 DSH
> **「看起来能跑」不算完成。**

## 1. 测试层级

| 层级 | 位置 | 说明 | 触发 |
|---|---|---|---|
| 单元测试 | `tests/unit/` | 纯函数 / 数据类 / 图算法（蓝图拓扑、Heat 计算、奖励池） | 每次提交 |
| 集成测试 | `tests/integration/` | 状态机流转、蓝图→战斗一局的完整链路 | 每完成一个系统 |
| 场景冒烟 | `tests/output/` | 每个 `.tscn` 能否独立实例化、无报错 | 每完成一个场景 |
| 手动验收 | 编辑器 + 导出包 | 双端输入、视觉、手感 | 每阶段 |
| 回归 | 全量 | 修复 bug 后必须补一条回归用例 | 每次修复 |

测试输出（日志、截图、报告）一律写入：

```
D:\GameDev\PixelFusion\tests\output
```

## 2. 必须验证的场景（每个功能至少覆盖）

## 3. 各系统的必测点

### 3.1 状态机（Stage 1）
- PREPARATION 停留 10 分钟 → 不自动进入 COMBAT。
- 连续快速点击「开始战斗」→ 只切换一次（防重入）。
- COMBAT → REWARD → PREPARATION 循环 10 次无内存/节点泄漏。
- 任意状态下退出到主菜单 → 无残留。

### 3.2 蓝图（Stage 2）
- 空蓝图进入战斗 → 不崩溃，有明确提示。
- 删除正在被引用的节点 → 连线一并清理。
- 环路连接 → 检测并提示，不死循环。
- 悬空端口 / 类型不匹配 → 拒绝连接或明确提示。
- 保存后重载 → 结构完全一致。

### 3.3 信号传播（Stage 3）
- 同一蓝图 + 同一输入 → 结果完全一致（确定性）。
- 执行顺序稳定（多次运行顺序一致）。
- 断开子图不参与执行。

### 3.4 战斗（Stage 4）
- Heat 达到阈值 → Overheat 触发且只触发一次。
- 波次清空 → REWARD 恰好进入一次。
- CORE 被摧毁 → RESULT。
- 0 敌人 / 1 敌人 / 大量敌人。
- 倍速切换不改变结算结果。

## 4. 测试编写规则

- 测试文件命名 `test_<被测对象>.gd`，放在对应层级目录。
- 每个测试必须能独立运行，不依赖执行顺序。
- 禁止依赖真实时间（用固定 tick / 注入时钟）。
- 禁止依赖真实随机（用固定 seed 的 RNG）。
- 禁止用 `print` 当作断言；必须有明确 pass/fail。
- 测试数据不得污染正式 `data/`，用测试专用 `.tres` 或代码构造。
- **禁止用「配置项等于某个值」代替「可见结果确实出现」**（v0.1.1，2026-10-03 实例）：
  规范若要求某个**视觉结果**（阴影 / 描边 / 高光是否存在、是否模糊），
  至少要有**一条像素级或渲染产物证据**证明它真的被绘制出来。
  只断言字段值不算 —— 实例：`shadow_size = 0` 时字段断言全绿，而阴影**一个像素都没画**，
  等于「断言了一个空实现」。取像素需真实渲染路径（`--headless` 的 dummy 驱动不产像素）。

## 5. 完成定义（Definition of Done）

一个任务只有同时满足以下条件才算完成：

```
[ ] 代码符合 02_CODE_STANDARD
[ ] 只修改了 ALLOWED FILES
[ ] 所有新增/修改逻辑有对应测试
[ ] 测试在本机实际运行过，并贴出结果
[ ] §2 的九类场景中适用的都已覆盖
[ ] 无 Godot 报错 / 无 warning 新增
[ ] 未越界引入范围外功能
[ ] 已更新 12_CHANGELOG.md（由 DSH 执行）
```

## 7. 禁止

- 禁止「我读了一遍代码，逻辑是对的」当作测试。
- 禁止只测 happy path。
- 禁止跳过失败测试直接交付。
- 禁止为了让测试通过而放宽断言而不说明。
- 禁止把测试写成永远 pass 的空壳。
