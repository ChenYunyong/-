# 06 — UI / UX 规范（UI & UX STANDARD）

> 状态：`FROZEN-DRAFT`（待用户批准）｜版本 v0.1.0｜维护者 DSH
> 本文件是 UI 实现的验收依据。所有数值为逻辑像素（基于 320×180 基准，双端整数倍缩放）。

## 1. 全局

| 项 | 规定 |
|---|---|
| 基准分辨率 | 320 × 180（16:9），整数倍缩放 |
| 安全区 | 四周内缩 8px；手机端额外汇总刘海/手势区，实际可用区由 `SafeArea` 容器统一处理 |
| 间距系统 | 4 / 8 / 12 / 16 / 24（只用这五个值，禁止 5、7、13 这类随手值） |
| 描边 | 统一 1px（清晰态）；禁止 0.5px、1.5px |
| 面板角 | 像素角（直角），圆角一律禁用抗锯齿圆角 |
| 阴影 | 仅允许 1px 偏移硬阴影，禁止模糊阴影 |
| 字体 | 中文像素字体（待 Codex 选定并经用户批准）；正文 ≥ 8px，标题 ≥ 12px |
| 触摸命中 | 最小 44×44 逻辑像素 |

## 2. Panel

| 属性 | 值 |
|---|---|
| 底色 | `NAVY_800` |
| 内层底色 | `NAVY_700` |
| 描边 | 1px `NAVY_600` |
| 内边距 | 8px（大面板 12px） |
| 标题栏高度 | 16px |
| 标题栏底色 | `NAVY_700` + 1px 底部 `GOLD_600` 分隔线 |
| 阴影 | 右下 1px `NAVY_900` |

## 3. Button — 五种状态（强制）

| 状态 | 底色 | 描边 | 文字 | 说明 |
|---|---|---|---|---|
| `Normal` | `GOLD_500` | `GOLD_600` | `NAVY_900` | 默认 |
| `Hover` | `GOLD_400` | `GOLD_500` | `NAVY_900` | 鼠标/触摸悬停，允许 1px 上移 |
| `Pressed` | `GOLD_600` | `GOLD_600` | `NAVY_900` | 按下，下移 1px |
| `Disabled` | `NAVY_700` | `NAVY_600` | `GREY_500` | 不可用 |
| `Selected` | `GOLD_400` | `BLUE_400` | `NAVY_900` | 当前选中项，外框 1px 蓝色 |

辅助按钮（次要操作）：底色 `NAVY_700`，描边 `NAVY_600`，文字 `GREY_300`。

**禁止**：用红色做普通按钮（红色只属于 HP/危险/伤害/警告）。

## 4. Node Card（蓝图节点卡）

| 属性 | 规定 |
|---|---|
| 尺寸 | 48 × 48（含 1px 描边），选中时外框 1px `BLUE_400` |
| 图标区 | 32 × 32，居中偏上 |
| 名称位置 | 卡片下方 2px，8px 字体，最多 6 个汉字，超出省略 |
| 类型标识 | 卡片左上角 6×6 色块：CORE=`GOLD_400`、FUNCTION=`BLUE_400`、WEAPON=`ORANGE_500` |
| 稀有度表达 | 卡片右下角小菱形：普通=无、罕见=`BLUE_300`、稀有=`GOLD_400`（**不得**用红色） |
| 连接接口 | 输入口在左/上，输出口在右/下；接口 4×4，未连接时描边闪烁（低频，≤1Hz） |
| 拖动 | 拖拽时半透明 70%，网格吸附 8px |

## 5. Tooltip

| 属性 | 规定 |
|---|---|
| 最大宽度 | 120px |
| 结构 | 标题（`GOLD_400`）→ 类型行（`BLUE_300`）→ 说明（`GREY_300`）→ 数值区（`BLUE_100`）→ 特殊规则（`ORANGE_500`） |
| 出现延迟 | 0.4s（触摸端：长按 0.5s） |
| 位置 | 跟随指针，靠近屏幕边缘自动翻转，不得超出安全区 |
| 内容 | 只显示该实体真实存在的字段；空字段整行隐藏，禁止显示 `N/A` |

## 6. 布局：MAIN_MENU（Reference A）

- 16:9，简洁。
- 必须元素：Logo · 开始 · 继续 · 设置 · 退出 · 工坊少女 · 猫咪 · 浮空岛背景。
- 禁止过度塞 UI；Logo 与背景是视觉主角。

## 7. 布局：PREPARATION（Reference B）

**完整蓝图构筑阶段。** 时间停止、无敌人、不战斗、不发射、不扣血。

区域结构由用户指令固定为 **左 / 中 / 右 / 下 / 右下** 五区。下列像素值为对 Reference B 的**实测反推**（方法见 §12），基准 320×180：

```
┌────────────┬────────────────────┬──────────────┐
│ 左：关卡信息 │  中：蓝图工作区     │  右：节点详情 │
│ x 19–86    │    x 96–214        │  x 221–310   │
│ (≈67px)    │    (≈118px)        │   (≈90px)    │
├────────────┴────────────────────┴──────────────┤
│ 下：节点仓库（高度待定，见下方警示）                │
│                                   ┌──────────┐ │
│                                   │ 开始战斗  │ │
│                                   │x246–310  │ │
│                                   │y148–162  │ │
│                                   └──────────┘ │
└────────────────────────────────────────────────┘
```

**实测依据**（Reference B，1672×941 归一到 320×180）：

- 竖直分栏边界出现在 **x ≈ 28%** 与 **x ≈ 68%**（边界强度为全图最高的 65.7% / 97.6%）。
- 左栏 **x ≈ 6%–27%** → 19–86px；中栏 **x ≈ 30%–67%** → 96–214px；右栏 **x ≈ 69%–97%** → 221–310px。
- **「开始战斗」CTA 是一块亮色区块，实测位于 x ≈ 77%–97%、y ≈ 82%–90%**（≈64×14px）→ 确认在**右下角**，与本规范一致。
- 画面外侧有一圈暖色木质外框（左 ~0–5%、底部 ~97–100%）。

> ⚠ **未能分离出「下：节点仓库」横条的独立边界** —— 该区域在实测中与中/右栏底部连成一体。
> 结构保留用户指定的底部条，但**其高度仍是暂定值**，须在 Stage 1 用编辑器/真机对照 Reference B 确认。

- 主区域必须全部服务于蓝图配置，禁止放置与构筑无关的装饰面板。
- 「开始战斗」按钮必须是右下角最显著的唯一主动作按钮。

## 8. 布局：COMBAT（Reference C）

- 进入 COMBAT 后，**蓝图主界面消失**，战斗画面占据整个主区域。
- 敌人生成、推进、CORE 运行、武器执行、Heat 计算全部可见、可读。
- 玩家主要职责是**观察机器的运行结果**，因此信息密度优先于特效。
- HUD 贴边，不遮挡战场。

**实测依据**（Reference C，1672×941 归一到 320×180）：

- **战场主区：y ≈ 0%–75%** → 320×180 下约 **y 0–135**。
- **底部有一条横贯全宽的深色条：y ≈ 75%–100%** → 约 **y 135–180，高 ≈45px**（占画面高约 25%）。
  该带内几乎全部是海军蓝系像素，判定为 HUD 条。
- 画面顶部有天空蓝透过（浮空岛背景）；左侧有一条暖色/深色竖边。

**据此规定**：COMBAT 底部 HUD 条高度取实测值 **≈45px（y 135–180）**，全宽，底色 `NAVY_800`，上沿 1px `NAVY_600` 分隔。

> ⚠ 实测的 25% 画面高比「贴边小条」的直觉更大 —— 这是参考图的事实。
> 若你想让它更紧凑（例如 24–32px），那属于**整体视觉方向的调整（GATE 3）**，需你确认后才改。

## 9. 布局：REWARD

- 战后奖励选择，选项 3 个（不足时补「跳过」）。
- 每项必须显示：图标、名称、类型、数值、特殊规则。
- 选择后回到 PREPARATION，玩家自行整理机器，再次自行点击「开始战斗」。

## 10. 交互硬规则（违反即打回）

1. 进入 PREPARATION 后**永远等待玩家**；禁止自动倒计时、自动开怪、自动开波。
2. `PREPARATION → COMBAT` **只能**由点击「开始战斗」触发。
3. COMBAT 期间不得弹出需要玩家即时反应的模态窗口。
4. 任何破坏性操作（删除节点、重置蓝图）必须二次确认或可撤销（Ctrl+Z / 触摸撤销按钮）。
5. 禁止 UI 直接修改战斗内部状态。
6. 所有交互必须同时支持鼠标与触摸。
7. 禁止在场景文件中硬编码颜色，必须走 Theme + Palette。

## 11. 可读性 / 无障碍

- 正文对比度 ≥ 4.5:1，标题 ≥ 3:1。
- 不得用颜色作为唯一状态区分手段。
- 必须支持「减少动态效果」开关：关闭流光、震动、闪烁。
- 文本必须走 key（`tr("...")`），不得硬编码在场景中。

## 12. 参考图实测布局证据（2026-10-03）

本节记录 §6 / §7 / §8 中布局数值的来源，避免它们被误当作「设计出来的」而非「量出来的」。

**方法**（纯标准库，无第三方依赖，可复跑）：

1. 对三张参考图做完整 PNG 解码（zlib + 逐行反滤波），得到 1672×941 RGB 原始像素。
2. **边界检测**：按列/按行统计相邻像素亮度差的均值，平滑后取局部极大值 → 得到面板竖向/横向边界的位置与强度。
3. **构成图**：把画面降采样为 78×40 的网格，每格取众数颜色类别
   （`#` 深海军蓝 / `~` 天空蓝 / `o` 亮白 / `w` 暖色 / `.` 其他），以 ASCII 输出 —— 用于在不依赖图像输入的前提下判读构图。
4. 脚本：`tools/ref_layout_probe.py`（边界检测）与 `tools/ref_compose_map.py`（构成图）。两者均为纯标准库、可复跑。

**结论可信度**：

| 结论 | 可信度 |
|---|---|
| PREPARATION 三分栏边界 x ≈ 28% / 68% | **高**（边界强度全图最高） |
| PREPARATION 的 CTA 位于右下角 x 77–97% / y 82–90% | **高**（与取色结果 `#F0C060` 独立吻合） |
| COMBAT 底部有全宽深色 HUD 条 y ≈ 75%–100% | **高**（该带几乎全为海军蓝） |
| MAIN_MENU 左暖色 / 中亮色 UI / 右天空蓝 | 中（构成图可读，但无法定位到具体控件） |
| 各区域的**精确**像素边界 | 低（插画有渐变与柔边，边界天然模糊） |

**因此**：本文件中的布局数值凡标注「实测」的，都允许在 Stage 1 对照真图微调；凡标注「暂定」的，必须在 Stage 1 确认后才能固化为冻结值。
