# 10 — 验收标准（ACCEPTANCE STANDARD）

> 状态：`FROZEN-DRAFT`（待用户批准）｜版本 v0.1.0｜维护者 DSH

## 1. 任务卡强制格式

DSH 派任务**不得**只说「实现蓝图系统」。必须写成：

```
TASK
  目标：<一句话，可验证>

INPUT
  输入：<依赖的文档/数据/上游任务>

OUTPUT
  交付物：<具体文件路径>

ALLOWED FILES
  允许修改：<精确文件列表/目录>

FORBIDDEN
  禁止事项：<明确不能碰的东西>

ACCEPTANCE
  验收标准：<可判定的条目，逐条可打勾>

TEST
  测试方法：<怎么测、测什么、结果记在哪>
```

缺少任一段的任务卡无效，执行 Agent 应退回。

## 2. 验收条目写法

好的验收条目：

```
[ ] 在 PREPARATION 停留 60s，不自动进入 COMBAT
[ ] 点击「开始战斗」后 200ms 内切换到 COMBAT 场景
[ ] 空蓝图进入 COMBAT 不崩溃，并显示提示文案
```

坏的验收条目（不接受）：

```
[ ] 蓝图系统能用
[ ] 界面好看
[ ] 性能没问题
```

## 3. 验收等级

| 等级 | 含义 | 判定者 |
|---|---|---|
| L1 自测 | 执行 Agent 自测通过 | Claude / Codex |
| L2 规范审查 | 符合 docs/00~10 全部相关规范 | DSH |
| L3 测试审查 | 按 `09_TEST_STANDARD` 有真实测试结果 | DSH |
| L4 用户验收 | 用户明确认可 | 用户 |

**L4 不可被任何 Agent 代替。**

## 4. 阶段验收门（Stage Gate）

| 阶段 | 验收门 |
|---|---|
| Stage 0 | 用户批准全部 `docs/00`~`12` 文档 |
| Stage 1 | 完整状态循环可跑通（占位图允许），PREPARATION 不自动推进 |
| Stage 2 | 蓝图编辑闭环：放置 / 连接 / 删除 / 保存 / 重载 |
| Stage 3 | 三类节点 + 信号传播确定性可验证 |
| Stage 4 | 一局完整可玩：波次 → 奖励 → 循环 → 结算 |
| Stage 5 | 每批素材单独获用户批准并集成 |

**阶段未过门，不得进入下一阶段。**

## 5. 用户验收的呈现要求

DSH 提交用户验收时必须提供：

1. 本阶段做了什么（对照任务卡逐条打勾）。
2. 实际验证过的路径（不是「应该可以」）。
3. 截图或可运行产物（导出包/录屏/截图）。
4. 已知问题与未完成项（不得隐藏）。
5. 明确的一句话请求：「请验收 / 请批准」。

## 6. 打回条件

任何一条成立 → DSH 直接打回，不提交用户：

- 无 CONSTRAINT CHECK
- 修改了 ALLOWED FILES 之外的文件
- 无测试结果
- 违反 `02_CODE_STANDARD` / `04_COLOR_SYSTEM` / `06_UI_UX_STANDARD`
- 素材未经批准进入正式目录
- 引入范围外功能
- 出现 C 盘写入

## 7. 验收记录

每次验收必须在 `12_CHANGELOG.md` 记录：

```
日期 | 阶段/任务 | 等级 | 结论 | 打回原因（如有） | 验收人
```
